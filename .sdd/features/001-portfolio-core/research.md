## Research items

### R-001 — Next.js 16.2.10 API surface (bundled docs = source of truth)

- **Source:** Constitution P-001 + spec risk "Next 16 breaking changes"
- **Why it matters:** every framework touchpoint (routing, transition, fonts, images) depends on it
- **Linked to:** REQ-005, REQ-006, REQ-010, REQ-020, NFR-004

**Investigation:** Step 2 (Project docs — `node_modules/next/dist/docs/`, agent research-next16, exhaustive read).

**Conclusion (key findings):**

1. **View Transitions supported**: `next.config.ts` → `experimental: { viewTransition: true }`; component `import { ViewTransition } from 'react'` (no canary install needed). Route navigations are React Transitions → auto-activate. Shared element morph: `<ViewTransition name="photo-{id}">` wrapping the element on BOTH pages — matching names auto-animate size+position. Props: `share`, `enter`/`exit`, `default="none"`. `<Link transitionTypes={['nav-forward']}>` (new v16.2) drives per-direction animations. CSS `::view-transition-old/new/group()` for custom timing; reduced-motion handled via media query zeroing durations. Sources: `01-app/02-guides/view-transitions.md`, `.../05-config/01-next-config-js/viewTransition.md`.
2. **`params`/`searchParams` are `Promise`** — sync shim REMOVED in v16. `async function Page({ params }: { params: Promise<{slug:string}> }) { const {slug} = await params }`. Client: `use(params)` or `useParams()`. New global typed helpers `PageProps<'/projects/[slug]'>`. `generateStaticParams` unchanged; `dynamicParams=false` → 404 unlisted; `notFound()` unchanged.
3. **Fonts**: `next/font/google` API unchanged; wire to Tailwind v4 via `variable: '--font-x'` on `<html>` + `@theme inline { --font-display: var(--font-x) }` in globals.css.
4. **Images**: `next/image` stable; static imports from anywhere / `public/`; `fill` needs positioned parent; v16 default changes (qualities `[75]`, TTL 4h) fine for local static assets. No `images.domains` (deprecated).
5. **Removed/changed**: `next lint` gone (scaffold already uses eslint directly); Turbopack default dev+build (no `--turbopack` flags; custom webpack config breaks build); `middleware`→`proxy`; smooth-scroll no longer overridden — opt in via `data-scroll-behavior="smooth"` on `<html>`.
6. **Dev server lockfile**: a running `next dev` blocks second dev/build — kill before build/verification.
7. Scaffold state: bare layout/page, `@import "tailwindcss"` in globals.css, empty `next.config.ts` — all v16-correct.

**Decision applied:** Use View Transitions API as the shared-element mechanism (REQ-010) — framework-native, zero extra dependency for the morph. All dynamic route code written Promise-params style. Fonts via `variable` + `@theme inline`.

**Confidence:** high (bundled docs, exhaustive).

### R-002 — 3D stack (React 19 / Next 16 compat)

- **Source:** spec risk "R3F/three compat with React 19.2 + Next 16"
- **Why it matters:** REQ-011, REQ-012, REQ-019, NFR-003
- **Linked to:** device 3D scene component

**Investigation:** Step 3/4 (npm registry live + official R3F/three docs + Next 16 bundled docs; Context7 quota exhausted → official docs used; agent research-3d).

**Conclusion (key findings):**

1. **Versions (peer-dep verified):** `three@0.185.1 @react-three/fiber@9.6.1 @react-three/drei@10.7.7`. fiber v9 = React 19 line; peers `react >=19 <19.3` — project's 19.2.4 fits (do NOT bump React to 19.3+ without re-check). No `@types/three` (bundled types).
2. **next.config:** `transpilePackages: ['three', '@react-three/drei']` required (official R3F guide; drei added defensively for CJS/ESM interop — drop if build clean).
3. **ssr:false constraint (Next 16 doc-verified):** `dynamic(..., { ssr: false })` forbidden in Server Components; allowed in client components → pattern: `'use client'` wrapper does the dynamic import with `loading:` fallback; server page renders wrapper.
4. **Perf:** `<Canvas frameloop="demand" dpr={[1,2]}>`; frames only on `invalidate()`. Scroll binding: pass framer-motion `MotionValue` prop into scene; `useEffect(() => progress.on('change', invalidate))`; read `progress.get()` inside `useFrame`, mutate group refs — zero react state per frame.
5. **Screen texture:** `useTexture('/screenshots/x.png')` (public/ path); MUST set `t.colorSpace = THREE.SRGBColorSpace` (default NoColorSpace; `sRGBEncoding` removed); `meshBasicMaterial map toneMapped={false}` for true-color screenshot.
6. **Device model:** procedural via drei `RoundedBox` (args/radius/smoothness) + screen plane + camera-bump geometry; `meshStandardMaterial` body.
7. **Fallback:** `<Canvas fallback={...}>` (WebGL unavailable) + error boundary for runtime context loss + optional pre-gate `webglOK()` canvas-context check. Static fallback = plain `<img>` device mockup.
8. **Gotchas:** Canvas parent needs explicit height; avoid drei `<Environment preset>` (remote CDN fetch) — use simple lights; `<ContactShadows frames={1}>` bakes once; everything three-related behind `'use client'` + ssr:false.

**Decision applied:** Procedural stylized device (no GLTF asset — resolves spec Q4), demand frameloop, MotionValue bridge, layered fallback per REQ-019.

**Confidence:** high (npm peers verified live + doc-confirmed patterns).

### R-003 — Animation + carousel stack

- **Source:** spec Q3 (shared-element mechanism) + carousel/text animation lib choice
- **Why it matters:** REQ-003, REQ-010, REQ-011, REQ-014, REQ-015, REQ-018
- **Linked to:** carousel, transitions, reveals

**Investigation:** Step 2/3/4 (bundled Next docs + node_modules grep + npm view; Context7 quota exhausted; agent research-motion).

**Conclusion (key findings):**

1. **Install:** `motion@12.42.2 embla-carousel-react@8.6.0 embla-carousel-auto-scroll@8.6.0`. Peers verified vs React 19.2.4. Import path `motion/react`; all motion usage in `'use client'` files. NOT framer-motion package.
2. **layoutId across App Router routes: NO** (confirmed — separate segments, no shared AnimatePresence). Shared-element = React `<ViewTransition name>` + `experimental.viewTransition: true` (matches R-001).
3. **ViewTransition runtime confirmed**: `exports.ViewTransition` present in Next's bundled React canary — no install. **TS gotcha:** `@types/react@19.2.17` exports it only in `canary.d.ts` → add project `.d.ts` with `/// <reference types="react/canary" />`.
4. **Fallback:** unsupported browsers degrade to instant swap automatically (doc-confirmed) — no JS fallback needed. Firefox 139+ (May 2025) supports same-document VT. Reduced-motion: CSS block zeroing `::view-transition-*` animation durations (MotionConfig does NOT cover native VT).
5. **Carousel: embla** (`loop: true, dragFree: true, align: 'start'` + `AutoScroll({ speed, stopOnMouseEnter: true, stopOnInteraction: false })`) — true infinite loop + drag momentum + pause-on-hover; ~5-6kb; hand-rolled motion marquee rejected (drag+infinite jank risk).
6. **Text reveal:** hand-rolled word/char split + motion variants stagger (overflow-hidden mask, `y: '110%' → 0`); GSAP redundant alongside motion.
7. **Scroll-driven:** `useScroll({ target, offset: ['start end','end start'] })` → `scrollYProgress` MotionValue → `useTransform`/`useSpring`; bridge to R3F per R-002 pattern.
8. **Reduced motion JS layer:** `<MotionConfig reducedMotion="user">` app-wide + `useReducedMotion()` for branching (e.g., disable AutoScroll plugin).

**Decision applied:** motion + embla + native View Transitions; resolves spec Q3.

**Confidence:** high (runtime exports grep-verified; API details medium-high — validate at build/verify step).

### Decision: shared-element transition mechanism

| Option | Pros | Cons | Verdict |
|--------|------|------|---------|
| framer-motion `layoutId` | familiar | does NOT persist across App Router route navigations | rejected |
